slopcop
Rules Feedback GitHub

Deterministic. No model. No server.

Slop stops here.

Point slopcop at a public repository on GitHub, GitLab, or Codeberg. Files are fetched straight from the host and scanned by the real linter compiled to WebAssembly. Nothing leaves your browser.

Try

GitHub token (optional)

Without a token, every scan from your network shares GitHub's anonymous limit of 60 API requests per hour, and each scan uses two. A token raises the limit to 5,000 per hour. Create a fine-grained token with public repository access and no permissions. It stays in this tab and is only sent to api.github.com. GitLab and Codeberg scans do not use it.

Starting…

Fetch

Files come straight from GitHub, GitLab, or Codeberg at the exact commit you pick. Dependency folders and oversized files are skipped before download.

Scan

The same Rust linter as the CLI, compiled to WebAssembly, runs in a background worker. No account, no model, no upload.

Review

Filter findings, read the evidence, jump to the line in the repository, and export the report as HTML or JSON.

What it catches

Observable problems, not authorship.

deadweight

Code and prose that exist without doing useful work: swallowed exceptions, placeholder markers, empty functions, trivial assertions, and comments that restate the code.

    vibecheck

    Patterns in prose and comments: stock transitions, assistant framing, hedging, forced symmetry, and uniform rhythm. One “robust” is fine. Density and repetition are not.

      papertrail

      Commit messages and branch history: placeholder subjects and autosquash commits that should never reach an integration branch. Needs a local clone.

        Take it to your terminal

        The CLI scans private code, staged changes, diffs against a base branch, and commit history. Run it from pre-commit, or gate CI with SARIF and GitHub annotations.
